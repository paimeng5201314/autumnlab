# 协作、复现与验收证据 · 0.5.1

AutumnOS 0.5.1 的修订应先明确问题触发条件、受影响合同及预期行为，再修改实现、文档与必要回归。制作人署名为派蒙。源文件、可运行产物和真实验收是不同证据层：文档更新不会重写已交付 EXE，合成身份测试不会完成真实登记，Linux 解析检查不会完成 Windows 原生交互。

每份结果至少记录构建 ID、源快照、实际命令/退出码、系统与工具版本、报告路径及覆盖范围。对结果分别使用 implemented（有代码）、partial（部分能力）、passed/failed（本次执行结果）、not_run（未执行）、blocked（缺必要平台、登记或信任材料）。不要把“已有实现”压成“已验收”，也不要把一次启动成功扩展成完整发布完成。

修复数据问题时在任务专用目录构造记录，比较失败前后旧字节与备份；禁止损坏真实用户存档制造用例。身份配置只记录公开字段与状态，测试令牌只能是明确的合成数据；真实 token、授权码、密钥和完整浏览器回调不进入日志或报告。身份说明文件解析成功本身不是认证成功。

SDK 或存储合同变化应同步 Host、Schema、类型声明、样例、文档与回归。重点覆盖 Unicode、完整消息预算、边界 key、命名空间冲突、旧数据读取、重复/未知 JSON 键和最终提交时的账号/权限变化。UI 文案修改要与实际事件处理核对，再在 Windows 检查显示、输入、焦点及持久化。

交付文档必须在两种形态分别试用：空目录放入单文件外层 EXE；另一个空目录完整展开目录版。各自从首次启动开始定位 Developer、创建/校验/打包模板、在真实宿主确认预览并关闭。记录所选 `--host` 目录与实际客户端一致，路径不能依赖开发者口头补充。操作步骤见 [第一个应用](first-app.md)。

仍需安排的独立矩阵包括社区网络通道、新布局升级回退、真实双账号与长期刷新、独立资源身份往返、Windows 10/干净系统/离线首启/多屏/DPI/输入法/触屏以及外部新人。生产签名、更新根与许可由有权人员完成收尾。保存失败报告和旧构建，用新 ID 关联重试结果，不覆盖失败以制造全绿历史。发布边界见 [宿主发布](host-publishing.md)。
