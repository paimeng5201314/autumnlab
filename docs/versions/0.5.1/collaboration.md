# 合同检查、兼容与协作

适用 AutumnOS 0.5.1、SDK 0.3.0、协议1。制作人：派蒙。集成负责人统一修改共享版本、Contracts、依赖、解决方案和发行流程；模块改动先明确文件所有权。没有Git仓库不是阻塞，本轮不初始化/提交/拉取/上传源码。真实快照按源文件字节生成，不将计划检查计为产品测试。

公开变更同时检查运行JS、d.ts、message Schema、26方法正反例、6事件、公开声明基线及对应中文页面。当前d.ts修正只禁止“已知字面量方法错误参数落到宽泛重载”，未知字面量/动态string仍发送并由宿主返回CAPABILITY_UNAVAILABLE，协议名和SDK版本不变。真实TypeScript负例使用@ts-expect-error，若错误不再产生则编译失败，不能只搜索接口名字。

专用开发管道协议1独立于应用消息协议1。developer.schema.json校验preview精确包路径/哈希、十四个固定debug动作、当前sessionId、有限跟踪和明确simulation状态；实际运行另检查当前用户ACL、目标宿主进程、帧限额、维护竞争及原生确认。新增测试模拟不改SDK0.3.0或26方法，不将模拟账号认证混入真实账号成绩。

合同工具使用固定TypeScript编译器、Ajv2020严格Schema和OpenAPI parser，禁远程$ref加载。store/release的引用是已注册manifestURN。每个结果记录工具版本、输入SHA、断言、退出状态和范围；不能把JSON.parse、文件存在或“已生成schema”当验证。公开基线更新必须经过兼容审阅，不能在测试运行时自动改黄金文件以求通过。

示例命令需要在全新目录用交付CLI执行。共享create/validate/pack引擎与原生开发者系统应用一致，调试只控制当前预览，不扩大到任意命令。发布材料检查不上传。文档链接本地解析，所有版本专题提供实际行为，不用空页计数；文档代码示例由真实类型fixture/样例源码和CLI复现支撑，最终证据列出实际运行范围。

审阅改动先说明触发行为和前后差异，再给测试、已知边界、迁移和恢复，不抹去失败历史。受控HTTP、模拟身份、合成时间、自动输入、实际窗口和物理操作分别报告。外部新人、真实Logto/第二账号、干净Windows10、签名与发布授权缺失不阻止独立开发，但相应门禁不能改成通过。参见[核心开发](core-development.md)、[入门](first-app.md)。
