# 数据、存档与恢复

适用 AutumnOS 0.5.1、SDK 0.3.0、协议1。制作人：派蒙。宿主数据根固定在入口旁AutumnOS_Data，不从工作目录推断。应用数据按账号/游客、AppIdentity和来源隔离；安装文件、私有设置、私有文件、存档、外部能力句柄和宿主账号密文不能混用。退出账号不删除存档，卸载默认保留，游客数据不在登录时静默迁移。

WebView2仅在Runtime/wv/<identity>保存浏览器缓存；identity是带版本域分隔符的SHA-256，输入含完整账号哈希和Application.BindingKey（appId、来源仓库/签名身份和source）。不同账号、应用、来源或签名身份拥有不同缓存；应用显示名称不改变身份。控制器使用InPrivate模式，浏览器缓存不作为持久存档或账号凭据。旧Runtime/<account-hash>/<binding-hash>及旧guest缓存保留原样，不复制或迁移到新缓存；Saves、AppData、权限持久化和账户归属路径保持原合同，更新不删除旧目录。

saves使用逻辑slot，storage/preferences使用逻辑key，均不接受磁盘路径。saves/storage键1–64位英数/下划线/连字符且拒设备名；preferences最大59位因内部pref_前缀，逻辑键CON也不形成设备名。SDK读文件适配限20KiB；32KiB消息总量是更早上限，不因为内部存储允许1MiB文件、16MiB账号应用总量、128文件、32槽位、128KiB存档就允许一次发送这些大小。不存在时exists=false且value/data=null，不清空当前未保存输入。

保存是有限JSON原子替换，保留安全备份；同值同格式可复用提交，业务上仍应防止重复点击和并发覆盖。格式版本1–1000000与应用SemVer分开。save-game复用原元素配对，当前存档格式2为player.nickname和turns，旧格式1是nickname和moves。读取时验证牌组数量、匹配索引、回合数和昵称长度；显式迁移真正转换并提交JSON和格式2，旧内容成为备份；只改版本号不算迁移。用“以旧格式1保存当前牌局（演练）”可以写入真实旧结构，再点击迁移、恢复并读回；这是当前样例构造的测试数据，不冒充旧版EXE升级。

save-game默认不自动写入。用户明确保存成功并主动勾选自动保存后，每完成一对可保存；自动保存只查既有授权，不弹权限窗。撤销/结束停止自动保存，失败保留原文件和当前游戏。恢复按钮调用真实saves.restore并读回，只处理当前账号应用上一份宿主备份，不执行任意目录恢复。损坏内容演示是本地验证拒绝、没有写盘，不能写成真实磁盘损坏测试。

系统文件选择器先获得files.open/save授权，再用新的真实点击选择。返回随机能力handle、文件名、大小和expiresUtc；不返回路径。句柄最长15分钟，绑定账号/实例/代次/来源与权限，最多64个；files.write一次消费并对既有目标保留备份，pickSave本身不会截断目标。关闭、撤销或切换账号后句柄不可复用。

TIMEOUT/USER_CANCELLED仅停止等待，读回确认之后再重试写入。宿主维护协调覆盖最终提交，不能更新时强杀游戏。用户整目录备份应先正常关闭主程序，复制完整AutumnOS_Data并保管账号保护密文；恢复只能在兼容版本和正确用户上下文按[排错](troubleshooting.md)操作，不将真实数据放开发者包。

独立开发预览继续复用AccountDataStore，来源身份包含确认包的SHA-256；即使预览与已安装应用appId/version相同，也不共享正式Saves/AppData。显式测试账号的账号命名空间另含本次预览随机范围和A/B/游客标记。同一范围切A→B→A可读回A自己的保存，B不能读A；关闭预览后新的范围不复用。测试文件保留在独立范围，关闭开发模式/reset不会删除它们或迁入真实账号；清理测试文件应先正常关闭预览并核对范围，不以“测试”名义删除整个AutumnOS_Data。预览权限决定只保存在内存，正式权限文件和账号凭据不写入。参见[受控模拟操作](first-app.md)。
