# 排错 · 0.5.1

先记录 AutumnOS 0.5.1 的准确构建 ID、交付形态、错误码与复现步骤，再判断资源、权限、账号或环境问题。日志和诊断包应只含允许的固定字段；不粘贴 token、完整回调、原始存档或凭据。开始前保留真实用户数据，优先在独立目录复现，不通过删除 `AutumnOS_Data` 或关闭验证获得表面成功。

| 现象 | 检查与处理 |
|---|---|
| 单文件版只有外层 EXE，找不到 Developer | 首次运行并等待准备完成；Developer 在 Data/System 的实际程序目录内。按 [第一个应用](first-app.md) 从客户端进程定位，不选旧 Product 目录。 |
| 目录版拷出一个 EXE 后缺 DLL | 恢复完整目录版的相邻资源；此要求只针对目录版，单文件外层入口本来就是单个交付文件。 |
| `DEVELOPER_HOST_UNAVAILABLE` | 宿主需已启动并启用开发者模式，CLI 与宿主使用同一 Windows 用户。检查 `--host` 是实际 Client 所在目录。 |
| `DEVELOPER_HOST_UNVERIFIED` | 核对运行进程与选定目录，拒绝通过绕过管道进程校验连接。单文件版不能使用外层目录作为 `--host`。 |
| `CLI_OUTPUT_ALREADY_EXISTS` | 原产物保持不变，为新创建/发布选择新目录。不要删除旧结果掩盖失败。 |
| `HOST_UNAVAILABLE` | 在宿主的原生预览中运行模板；普通浏览器页面没有原生 SDK 桥接。 |
| `USER_GESTURE_REQUIRED` / `PERMISSION_REVOKED` | 从真实输入操作请求 prompt 权限；已撤销权限由用户在设置中处理，不循环重弹。 |
| `AUTH_REGISTRATION_UNVERIFIED` | 检查公开登记说明的格式与字段；说明可读仍不等于真实登录。不要手工写认证成功状态。 |
| `RESPONSE_TOO_LARGE` 或数据预算拒绝 | 按完整 UTF-8 JSON 信封检查内容、转义和 ID 开销，保留旧存档；禁止截断读取或虚报保存成功。 |
| 已安装却不能运行 | 普通社区包仍受受控运行门禁限制，见 [网络边界](network.md)。不要冒充内置包。 |

单文件准备取消/失败后可能保留 `.prepare-*`，多个种子也可能留下不同 `System/Product-*`。它们可能包含当前运行、事务恢复或旧版本所需资源；现阶段缺少完整安全回收工作流，不能按“看起来旧”删除整个目录。先关闭自有实例并保留诊断证据，再由具备资源归属信息的维护工具处理。

配置或存档损坏时使用设置中的只读恢复检查；仅对已验证备份执行明确确认的恢复。已有 `.before-restore` 冲突、未来 schema、权限失败或只读磁盘应停止并保留字节。系统签名/更新信任缺失是发布配置条件，不能以管理员运行、关闭 TLS 或放行未签名内容解决。

提交问题时注明“静态检查”“模拟测试”或“Windows 原生运行”，附脱敏报告路径和未执行范围。历史成功不能说明本次修订已通过，详见 [协作与证据](collaboration.md)。
