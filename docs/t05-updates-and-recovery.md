# 主程序更新、指定版本与恢复

Lab Chronicles AutumnOS · 制作人：派蒙。本文描述本次源码实现；运行结果与未验收项见 [本轮验收记录](update-first-login-validation.md)，历史结果保留在 `AUTUMNOS_PROGRESS.md`。

## 用户操作

在现有「设置 → 系统更新」查看当前显示版本、可比较版本、当前渠道、检查状态、上次检查和上次成功时间。主程序策略保存在 `AutumnOS_Data/Updates/state.json`，与商店内单个应用的预览、固定版本设置独立。新用户默认关闭「接受预览版邀请」；旧 `Config/system-update.json` 的明确预览选择只在尚无主程序策略文件时迁移。

每次真正启动主进程异步检查一次。重复双击只激活原实例，不重复检查；启动检查与手动检查合并并发请求。首次配置未结束时只读取元数据，提示等到完成配置后出现。无网、超时或限流不阻止进入桌面；设置保留原因与上次成功时间，失败缓存不会伪装成最新检查成功。

关闭预览时，自动候选只来自官方仓库 GitHub `/releases/latest` 的稳定发行版；打开后，在 Latest 稳定版和分页查询到的已发布预览版中选出严格高于当前版本的最高兼容可信版本。GitHub `draft` 永远排除，`prerelease` 决定稳定／预览分组，不依据标题。开关关闭不会卸载当前预览版或自动降级；尚未应用的预览任务会被阻止。当前预览高于稳定版时可继续使用，或主动选择兼容稳定版回滚。

发现候选后先查看当前和目标版本、渠道、时间、大小、兼容性及该 Release 的发布说明，再选择「确认更新」。在确认以前只查询小体积元数据，不下载程序包。「暂不更新」在本次会话不再弹同一目标，但设置仍可查看；下一次真实启动可以再提醒。

下载并验证成功后选择「稍后重启」或「重启并安装」。稍后仅保存验证完成的待安装记录：普通退出、下次启动和计时器都不会自动安装。重启安装前仍会复查原目标、当前策略和运行中的游戏／应用；请先保存并正常退出，不会强制结束有用户状态的应用。取消下载或确认不会留下新的授权安装任务。

「更新到指定版本」与「回滚到指定版本」共用分组下拉框。稳定版、预览版分组标题不能选择；历史发行版可继续加载。不可安装版本仍可查看说明，但确认按钮禁用并解释原因。升级只允许更高版本，回滚只允许更低版本，不提供同版本重装。预览开关关闭时可以阅读预览说明，但必须主动开启并成功保存后才可安装。

选择非渠道推荐目标时，「切换后固定此版本」默认勾选。固定只在安装及核心启动健康验证成功以后保存；失败不会假装目标已安装。固定后每次启动仍检查，在设置显示结果，但不弹常规升级提示。选择「恢复跟随更新渠道」清除固定并重新检查，仍须确认才下载和安装。

## 版本身份与发布源

官方源固定为 `paimeng5201314/autumnlab`；没有任意仓库输入入口，也不需要 GitHub PAT 或账号登录。已有 GitHub 代理设置只影响传输，不改变受信仓库、签名和资产校验。

显示名称、GitHub tag、签名清单 `version`、`buildId` 和 Release／资产 ID 分别保存。`SemanticVersion` 按 SemVer 2.0 比较：数值预发行段正确比较，正式版高于相同核心预发行版，build 元数据不改变优先级；允许的 `v` 前缀在 Release 边界规范化。历史 `meta`、日期标签不猜成 SemVer，必须由签名清单的 `releaseTag` 明确绑定。文档测试中的版本号都是合成示例，不是新的产品发行号。

2026-10-10 核对到的官方记录：稳定版 tag `meta`，预览版 tag `meta0.0.2-20261007`。两者均缺少受信自动更新清单、签名及 ZIP 资产，所以可显示历史发行记录，不能声明能够自动安装。工程默认版本与历史交付内部版本不同，本次未自行修改产品发行号。生产信任根仍须维护者提供，不能把测试公钥放进生产集合。

## 模块与状态

| 模块 | 职责 |
|---|---|
| `AutumnOS.Update/UpdateService` | 唯一主程序策略、候选和历史列表、并发检查、精确目标同意、验证后暂存与恢复、固定状态 |
| `UpdateMetadataClient` | 有界响应、条件请求、20 秒单次超时、服务错误有界重试、持久限流冷却；缓存不扩大信任 |
| `UpdateManifestCodec` / `UpdateSignature` / `UpdatePayload` | 严格清单、签名／有效期／可信根、摘要／长度／文件表、解包路径限制 |
| `UpdateAuthorization` | 单次手动回滚绑定安装来源与完整目标签名摘要；不全局降低安全序列 |
| `Shell/UpdateUi` / `UpdateDialogsUi` | 启动提示、策略保存、版本选择、下载确认、明确重启操作 |
| `Shell/NativeReleaseNotes` | 有大小和块数限制的原生 Markdown 子集；原始 HTML 仅文字，不加载脚本或图片，无宿主桥接；外链只在点击后按 HTTP(S) 校验打开 |
| `UpdateProtocol/UpdaterHandoff` / `UpdateTransaction` | 原有业务单实例、维护锁、独立进程交接、文件备份、逐文件事务、健康验证、失败恢复 |
| `UpdateDataSnapshot` / `PortableEntryBinding` | 限定配置快照、兼容性检查、原单文件入口的已更新身份记录 |

工作状态为检查 → 发现版本／等待确认 → 下载 → 验证 → 等待重启 → 维护复查 → 交接／安装 → 核心健康验证 → 完成。错误和中断进入明确失败或恢复状态。确认绑定官方仓库、Release ID、tag、SemVer、RID、资产 ID、长度、摘要与清单摘要；后续发布 B 不会改变已经同意的 A。不使用 `/latest/download`。下载前、重启交接及独立更新器应用前检查原 Release 身份；撤回、改草稿、换包、关闭预览或验签失败均停止。

## 安装、回滚和数据边界

普通升级、指定升级和回滚共用现有独立更新器。更新先验证完整旧安装和暂存负载，再备份、写可恢复日志、替换受管理文件；不运行 Release 说明中的命令。应用失败或新进程核心健康失败，恢复已验证旧程序和对应配置快照。单纯进程启动或退出码零不算成功，失败构建记录阻止自动重试循环。

目前支持双方都实现新协议、桌面数据契约 1 的版本对；目标必须明确支持引导状态 v2。手动同格式回滚保留当前设置，并为这次切换备份当前设置。更高／未知数据格式、不可逆迁移和不支持新引导状态的旧版明确禁止；本轮没有通用跨格式快照迁移或强制忽略兼容性入口，不能把任意 GitHub 历史 EXE 称为可回滚版本。程序的最低安全版本与失败构建保护仍有效。

快照白名单仅 `Config/desktop-preferences.json` 与 `Config/desktop-layout.json`，记录对应程序身份、格式、时间及摘要，并在首次修改程序前完成。首次引导完成状态、主程序渠道策略、身份凭据、应用、存档不进入快照。健康失败只恢复白名单配置；正常手动回滚保留当前同格式配置。快照校验或备份失败阻止破坏性切换。

单文件外层 `AutumnOS.exe` 的嵌入种子与运行目录 `AutumnOS_Data/System/Product-<种子摘要>` 分开。成功更新保留同一运行根的受管理文件；持久入口记录在该运行目录外，防止运行缓存丢失后默默重新展开旧代码。正常快捷方式仍指向原 EXE。此防护需要新的外层 EXE，旧外层入口和旧独立更新器不会因业务程序更新自动学会新协议；首个过渡版本必须完整更换单文件发行包并保留原 `AutumnOS_Data`。参见 [发行工程](t05-release-engineering.md)。

事务、备份与恢复记录位于实际程序根 `.autumnos-update`；单文件布局下不是 EXE 外层目录。故障时保留记录，不删除未知文件或整个数据目录。缺少生产公钥、可信附件、有效兼容说明或可用 Windows 验收时保持失败关闭。
