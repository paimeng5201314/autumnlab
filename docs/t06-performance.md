# T06 本机性能实测计划

本计划在执行前写入源码。测试入口是同一最终便携交付中的 `AutumnOS.exe`，先完整复制到新的中文隔离目录，排除已有 `AutumnOS_Data` 与更新事务目录，逐项核对交付清单哈希。由集成负责人排他调度 `scripts/Measure-T06Performance.ps1`；与其它 UI 演练、全局维护互斥 fixture 串行执行。

事前工程试验目标为：首次可见且可交互窗口不超过 10 秒；完成欢迎后的三次再次启动各不超过 5 秒；打开设置、启动游戏、返回桌面、继续原实例、结束游戏的观测响应各不超过 2 秒；同一游戏后台状态占用不超过整机 CPU 的 5%；进程树峰值工作集总和不超过 600 MiB。这些是本机测量目标，不是制作人承诺，也不替代正确性门禁。超标必须保留原数值和结果，不能以改目标、减少样本或删报告变成通过。

已知参考机器为 Windows 11 Pro 10.0.26200，Intel Core i7-12700，12 核/20 逻辑处理器，物理内存 16,908,730,368 字节。脚本还会采集执行时 OS、CPU、逻辑处理器、内存、原生窗口和客户区几何及 `GetDpiForWindow`；以实际报告为准。

本次预定采用产品默认非最大化窗口 1180×880 像素；小工作区按现有产品算法缩到工作区宽高减 48 像素，不改派蒙确认的尺寸策略。开始实测前读取的 `GetDpiForSystem` 为 96（100%）。报告同时记录真实窗口 DPI；若与 96 不同，注明该次环境差异，不将它算成已覆盖其它 DPI 的矩阵。此轮不更改系统缩放。

首次启动计时从启动稳定入口前开始，到驱动确认原生窗口由精确持有的子进程拥有、UIA 的欢迎操作可见且启用。欢迎操作完成后正常退出，同一安装和数据目录再启动三次，计时终点为桌面操作可见且启用。记录各次原值、首次和复启的最大值/中位值。没有清理操作系统文件缓存、重启电脑或制造冷缓存，不能称为冷启动。计时包含启动器解析、UIA 查询和测试输入开销，是端到端观测上界；轮询间隔为 150 ms，标记其采样误差，不把结果当作内部毫秒级埋点。

第三次复启后，通过原生入口运行内置元素配对。记录同一 `instanceId` 前台、后台、继续及资源完全释放后的状态，前台/后台/结束后分别连续采样 12 秒（参数范围 10–15 秒）。进程树包含稳定入口、业务进程以及由已持有父进程的创建/退出区间、路径和会话绑定的真实后代（含 WebView2）；不按进程名把用户浏览器算入。每 500 ms 记录 CPU 时间、工作集和私有内存，CPU 按累计进程 CPU 秒 / 实测墙钟秒 / 执行时逻辑处理器数归一化；工作集求和包含共享页重复计数，是保守的进程树总量。短于采样周期且未被发现的进程不能计入，报告明确此限制。结束后仍记录剩余 WebView 进程；不以窗口消失推断全部资源已释放。

只有当前测试持有、身份仍一致的窗口可接受输入和正常关闭。已有用户实例时拒绝开始，不强杀进程，不清缓存，不改系统设置，不安装全局依赖。截图仅捕获测试窗口客户区。保留隔离目录、报告、每次启动 PID/创建时间、生命周期日志和所有失败；未跑项保持 `not_run`。

本脚本不测 GPU、触屏、帧时间、动画掉帧、60 fps、Windows 10、低配机、断电、真实账号或安装包。结果只能支持记录的机器、构建身份、资源状态和操作。完整本机测量命令与结果由实际报告及进度文档关联，不套用历史 T05 成绩。

执行示例（交付路径由负责人在冻结构建后填写）：

```powershell
pwsh -NoProfile -File scripts/Measure-T06Performance.ps1 `
  -ExecutablePath '<最终包>/AutumnOS.exe' `
  -ReportDirectory '<全新报告目录>'
```
