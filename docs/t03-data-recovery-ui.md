# T03 本地备份检查与恢复

制作人：派蒙。适用于 T03 开发包；Windows 界面实际验证结果以该包的运行报告为准。本页描述设置内真实宿主入口，不是应用 SDK 授权，也不代表 T05 更新维护已经完成。

## 入口与只读检查

打开「设置 → 开发者诊断 → 本地数据恢复」，选择「检查配置与当前账号存档」。检查通过 `VersionedConfigurationStore.Load/InspectBackup` 与 `AccountDataStore.ListSlots/InspectSaveRecovery` 完成，不直接扫描任意磁盘路径，不修改文件或为应用授予权限。

配置范围是当前 EXE 旁 `AutumnOS_Data/Config/developer-mode.json` 的受支持 schema 1 `{enabled:boolean}`。存档范围是当前游客或已验证账号、真实安装记录中 bundled 来源的元素配对。显示的槽位取自该绑定的存档服务；主记录损坏时仍单独检查样例固定 `game` 槽位的备份。界面只在实际存在且通过校验的备份上呈现恢复操作。

检查账号与代次是冻结快照，结果返回时账号变化则丢弃旧结果。游客、A/B 账号、不同应用来源保持各自命名空间；不使用昵称或邮箱定位存档，不跨开发包目录搜索或迁移数据。

## 恢复开发者模式配置

1. 先保存开发预览中需要保留的进度，再选择「恢复开发者配置备份」。取消确认不关闭预览或修改文件。
2. 确认后重新检查备份，结束开发预览并撤销旧调试能力，再调用 `RestoreBackup(confirmed:true)`；普通元素配对游戏保持运行。
3. 如果存在主配置，恢复前复制为 `.before-restore`；有效 `.bak` 保留。已有 `.before-restore` 与主文件同时存在时报告 `CONFIG_RECOVERY_CONFLICT`，不覆盖这份恢复记录。
4. 重新读取实际配置，按受支持的真实 enabled 值恢复开发者开关、能力和桌面入口。关闭的旧预览不会自动重开；配置无法安全读取时能力保持关闭。

配置备份缺失或损坏时只显示实际错误，没有恢复按钮。`CONFIG_FUTURE_SCHEMA` 不降级读取；业务值不是严格的 `{enabled:boolean}` 时显示 `CONFIG_INVALID_VALUE`。取消、磁盘写入和权限失败保留原文件及已生成的恢复记录；原主文件本来不存在时不会声称曾保存一份主文件。

## 恢复元素配对存档

1. 在当前账号槽位下拉列表选择已有备份的槽位。界面显示备份是否通过应用来源、账号与内容校验。
2. 点击「恢复所选存档备份」，确认所选账号/槽位。接着使用已有保存并关闭对话框处理当前游戏与开发预览；请在游戏内先保存。任一步取消都不会执行恢复或强制结束实例。
3. 明确确认关闭后再次校验冻结账号，调用 `RestoreSave(slot)`。最终提交在身份代次租约和真实关键写入协调内执行；账号已变则 `SESSION_EXPIRED`，不会写入新账号。
4. 备份恢复为主记录；原主记录存在时保留为 `.before-restore`，有效备份保留。再次打开游戏创建新实例并读取恢复后存档，不暗中改写仍在运行的 WebView 内存。

`SAVE_RECOVERY_CONFLICT` 表示已有恢复记录，界面不覆盖它。备份损坏、绑定不一致、配额/磁盘/访问失败均保留原文件；错误时不切换账号、不删除存档，不通过清空旧数据绕过失败。外部进程在检查后修改文件时，存储服务在实际恢复中重新验证，界面检查不是授权任意字节写入。

## Windows 检查步骤

- 无备份账号：显示「暂无备份」，不能触发恢复。
- 配置两次修改产生备份：确认恢复后真实开关、桌面开发者入口和持久化值一致；开发预览关闭，普通游戏实例保持。
- 游戏两次不同保存产生备份：先取消关闭，核对实例 ID/未保存输入不变；再次确认恢复，原实例关闭，重开后读取备份内容。
- 隔离副本中破坏主记录而保留有效备份：列表错误仍显示，固定 game 备份仍可核验和恢复；不破坏真实用户数据来造测试条件。
- 已有 `.before-restore`：恢复停止，原主记录、`.bak` 和已有恢复记录哈希不变。
- 账号在检查或恢复期间变化：旧结果不能成为新账号的操作；检查当前账号后重新选择。

自动化控件 ID：`DataRecoveryRefresh`、`DeveloperConfigBackupStatus`、`RestoreDeveloperConfig`、`SaveRecoveryAccount`、`SaveRecoverySlot`、`SaveRecoveryStatus`、`RestoreSaveBackup`、`DataRecoveryResult`。服务层故障注入测试与真实 Windows 入口检查分别记录；文档步骤本身不是验收通过证据。
