# Autumn Store 本地检查点

Lab Chronicles AutumnOS · 制作人：派蒙。适用 `0.4.0-t04-store`，Windows 原生系统应用。完整 T03 收尾由派蒙暂缓；本增量不是 T05 主程序更新或正式发行验收。

## 用户流程

桌面与 Dock 的商店打开同一个原生页面。发现直接匿名查询 `topic:autumnos-app is:public`；搜索不会要求 Logto 登录、GitHub PAT 或跳转外部商城。空结果与网络失败分开呈现。仓库 Topic 标记 PM、SQ、未分类或冲突，PM 的“受认可”是仓库自标、未核验，没有额外权限与认可名单。

详情先重新核对 repositoryId，再读取展示清单、Release 元数据和 `.autumn` 附件。草稿、源码归档、EXE、缺少清单、哈希/权限/版本不匹配、宿主不兼容均不能安装。版本页有稳定/预览与兼容筛选，并能继续读取历史页。发现页兼容、离线、运行环境、有更新筛选作用于已经载入的详情；界面明确说明范围，未读取详情的条目不被猜测为匹配。首次发现不批量遍历所有 Release，以避免公开 API 限流。

下载确认展示应用、来源与权限。成功顺序为：排队 → HTTP 下载 → 大小/摘要检查 → 等待安装 → 包结构与三层合同检查 → 暂存 → 原子提交注册 → 桌面入口与系统商店通知。下载完成不等于安装完成；同一请求幂等，应用使用中的资源不覆盖。原生通知中心的商店通知按 appId 去重、最多 20 条、仅本次启动，可清除或打开“我的应用”；它属于宿主安装状态，不冒用游戏通知权限，也不宣称 Windows toast 已实现。

“我的应用”提供固定当前版本、独立预览开关、选择历史版本、修复与卸载。后台游戏也属于运行中，需保存后真正结束才能更新/修复/卸载。降级检查所有账号/游客存档格式并生成备份；不兼容不会覆盖。卸载默认只撤销注册，保留存档与历史资源恢复缓存，不声称立即释放全部磁盘空间。关闭后再次运行是新实例。自0.4.1起按派蒙新决定：单击图标继续，双击桌面空白处打开全部运行实例的切换器；长按/右键继续与结束保留。桌面图标支持真实排序保存，见 `desktop-multitask-arrange.md`。

本地“安装 .autumn”使用 Windows 文件选择器，商店内容区也支持拖入单个 `.autumn`。两者与网络安装共用 `ApplicationInstallService` 和包校验。来源 `local` 不得接管已安装 GitHub 应用；修复另有原来源、原版本、原摘要的专用路径。本检查点未注册 Windows `.autumn` 文件关联，未接通深层链接安装。

## 安全边界与身份

一般社区应用可以读取资料、下载并安全安装，启动继续受 T01 第三方 WebView 网络隔离验收限制。不能因 PM、已下载或已安装就执行任意 Web/EXE；没有关闭 CSP、TLS、SDK 速率或有界去重。包散列提供一致性，并不证明发布者可信。

安装注册以 appId 和不可变来源标识绑定。用户 ID、Logto 令牌不进入目录请求或安装协议。账号切换仍使用既有 epoch/应用关闭协调；受控测试源在准备账号切换时停止。现有 `elementpairs` 的游客路径、首启记录、双栏设置、原有 SDK 与登录保持未重建。旧包不会被本包覆盖；不同发行目录仍各自保留数据，单实例唤回已有实例不改变其目录。

注册表与下载收据分离。提交后退出时，已完成注册是事实；收据更新失败记待协调，重启仅在来源、版本、摘要、权限、格式和全部已安装字节一致时补写完成。损坏记录/历史保持并报告，不依赖文件存在就宣告安装成功。使用 `CriticalOperationCoordinator` 协调实际写入，这不是 T05 更新维护交接协议。

## 明确的本地测试源

在游客环境中进入设置 → 开发者诊断，打开开发模式；桌面开发者工具 → 本地商店集成测试 → 确认。屏幕显示“本地集成测试数据，不是 GitHub 实时结果”。这是显式测试能力，不是生产商店备用商品源。

`StoreTestSource` 绑定 127.0.0.1 随机端口、随机访问能力，有限 GET、请求头和连接数；经同一个目录、下载与安装服务读取真实 HTTP 字节。包 appId 为 `cn.labchronicles.storeprobe`，独立于元素配对及其存档。外部索引必须与程序集内嵌索引完全一致，包哈希也必须匹配，不能通过修改测试文件夹放行另一应用。仅该编译内样例允许受控内部运行，没有仓库认可名单。

样例 1.0.0/1.1.0 为格式 1，1.2.0-preview.1 为预览，2.0.0 为格式 2；1.9.0 有故意错误的发布摘要，必须失败。HTML/JS 从包内运行，不 fetch 外网。真实 SDK 读写测试文字、请求存档权限；宿主日志记录实例 ID，页面不伪造该 ID。关闭开发模式撤销测试监听和实例，先询问保存；正常关闭会结束自己的监听。重启只回到公开 GitHub，历史测试安装/存档保留，测试源不自动启用。

## Windows 验证与故障排查

先正常退出已有 AutumnOS 窗口。构建入口仍为 `scripts/Build.ps1 -BuildId <新T04-ID>`、`scripts/Test.ps1` 和 `scripts/Test-Source.ps1`。`scripts/Package.ps1 -Checkpoint T04 -Stage Prepare` 创建独立目录，`-Stage Finalize` 对该目录的字节副本跑真实商店与 T02 桌面，再直接启动最终路径 EXE，最后才生成 ZIP 与新快捷方式。所有运行数据保留在各自目录，ZIP 按冻结白名单打包，排除 AutumnOS_Data。

`Test-T04StoreSmoke.ps1` 驱动真实 UI；`Test-T04DeveloperTools.ps1` 驱动实际 CLI 进程。`AutumnOS.Tests --probe-store --report <新路径>` 使用生产网络适配器只读探测，报告 HTTP/限流/cache/查询结果，不把模拟结果称为 GitHub 结果。受控 HTTP、合成 handler、真实网络、原生界面分别记录。

无结果：检查公开查询的实际结果与 Topic；不存在合规 Release 时仍可浏览，安装专项保持未执行。网络失败：设置保存和 API 连接测试不等于附件加速有效；须读取真实合规附件后测试附件连接。包/来源冲突：保留旧安装，检查 appId/repositoryId/三层字段，不以重新下载绕过。运行忙：后台也持有租约，保存并结束实例。降级格式不兼容：保留高版本与存档/备份，使用可读该格式的版本。持久记录损坏：原文件保留，先保存证据，不删 AutumnOS_Data。

本轮证据与缺项以 `AUTUMNOS_PROGRESS.md`、构建目录测试报告为准。UI 截图不代替触控、DPI、Windows 10 或任意第三方安全验收；真实公开 Release 和真实加速服务不可用时保持 blocked/not_run。T03 未执行项与 T04/T05/T06 交叉项继续保留。
