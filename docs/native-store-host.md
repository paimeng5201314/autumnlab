原生浏览器请求失败时，站进程仍按原有协议转发失败并关闭通道。客户端仅将严格校验的固定阶段、内部错误类别、数值 HRESULT 和有界自检概要记入 nativeHost.FailureCode；不记录原始异常消息、网页内容、路径、账号或挑战 nonce。该诊断不是隔离证明，不改变成功条件、超时、隔离策略或退出观察要求。

画面在同步 LosingFocus 事件确认新焦点目标不是自身时立即推进输入代次并丢弃排队输入，切到后台使用相同边界；不等待迟到的 LostFocus，避免漏掉快速离开后返回的边界或清除新的中文组合输入。重新聚焦后的原生 KeyDown 仍检查 KeyStatus.WasKeyDown，物理键尚未释放的重复事件不会因本地 held 已清空而取得新的按键或字符资格。已取出但尚未写入原管道的输入也通过该代次的取消令牌失效。原始对端核验后、占用管道序号前再次检查取消。已开始的写入继续等待真实回执，随后按原顺序执行 ResetInput；新输入等待重置回执，不能把取消请求当成已投递或已退出。队列最多32项、每项4096字节，代次耗尽时关闭。纯队列/信号量回归只验证上述合同，真实 UI 和原生管道仍须单独验证。

AppContainer 内读取暂存资源时使用原始文件对象身份绑定：站进程先完成路径、封存和句柄固定校验，再经原继承管道传递每个资源的卷标识、文件索引、长度和 SHA-256。浏览器核对实际打开句柄的同一对象身份、文件类型、长度和哈希，不依赖受限环境中的 DOS 盘符反向解析。父端完整路径校验保留。这针对 `GetFinalPathNameByHandleW` 的 DOS 映射在 AppContainer 下可能失败的情况（[Microsoft API](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfinalpathnamebyhandlew)、[STL 同类问题](https://github.com/microsoft/STL/issues/6286)）；适用性仍以本轮真实运行报告为准。

商店的“打开”入口向 WebAppHost 交付注册的应用版本和运行租约。客户端核验安装目录，将安装包的 SHA-256 与原始归档比对，从归档重建逐文件摘要。新安装会保留原始归档。旧安装可以使用同一下载回执的归档。独立宿主和固定版 WebView2 的文件表在构建时写入客户端程序集，不从应用包、应用清单或运行目录自行取得信任。

Shell 在新建的会话目录中复制并封存这三组文件。受限浏览器不能写入或替换其中的代码。父进程持有原进程句柄，检查内核管道对端、私有窗口站、进程令牌、原 Job 成员和引擎路径。站进程创建隔离的桌面和 profile，再创建零能力 AppContainer 浏览器。此机制使用 NETONLY，本机会产生真实的 Windows 登录会话和审计；不使用登录密钥或真实账号密码。

父进程在实际游戏入口上生成一次性解析挑战。浏览器只加载受控引导内容，保持原生网页资源请求未完成。双方均验证网络策略及文档绑定后才允许插入游戏 HTML。窗口展示真实 WebView2 PNG 帧，首次完整解码成功才记录 native_first_frame。视口按实际游戏区域的宽高比调整；800×600仅为启动默认值，仍限制每帧最多480000像素、单边2048和PNG传输1MiB。较大窗口等比放大帧，整数取整可能留下数像素细边，不再保留固定4:3大块空白。输入协议不接受任意浏览器命令。切换到后台会重置受限窗口中仍按下的键、鼠标及组合。中文输入处理原生组合事件，有界传输；完整中文输入法和硬件矩阵需目标桌面实测。

尺寸更新使用仅含两个小端整数的8字节Resize命令，沿原鉴权通道同序传输。宿主合并快速缩放，只在旧尺寸的已排队输入获得回执、组合输入结束后调整；旧按键及鼠标状态先释放。原浏览器STA验证边界、更新Bounds并回执，父进程随后要求PNG头部与完整解码尺寸均精确匹配。新尺寸帧显示前暂停坐标和普通按键输入，点击映射始终使用已显示帧的真实尺寸；不使用裁切或非等比拉伸掩盖留白。此修复不提升完整隔离验收状态。

SDK 回复在最终的权限、账号、实例和代次检查下取得投递许可。失效的许可不能排队。只有原浏览器 STA 实际调用 PostWebMessageAsJson 后返回的匹配回执才算投递，撤权屏障与投递共用顺序。失去连接时结果不确定。退出要从原始内核对象确认；还须等投递清空、封存目录清理完成才释放游戏和维护租约。

普通发行构建仍拒绝未经完整验收的第三方执行。`Build.ps1 -LocalIsolationAcceptance` 仅为本次新建的独立验收位置嵌入资格；没有环境变量、开发开关或应用认可名单。验收目录必须运行在本地 Windows 10 22H2 / 11 x64 普通用户桌面。全链验收须核对第一帧、实际游戏可操作、保存结束并由新实例读回、真实系统剪贴板与网络接收端正反对照、账号切换及撤权、原进程退出和系统矩阵。仅通过构建、文件访问控制或本机 Server 负例不能放行。

验证入口为 `scripts/Test-NativeStoreAcceptance.ps1`，按当前构建 ID 核对交付文件。Preflight 仅检查交付；ServerNegative 只能验证拒绝；ClientTrial 记录普通桌面实操。完整成绩以对应构建目录的记录为准。

跨机器本地验收包可以完整解压到当前普通用户的 `%LOCALAPPDATA%\AutumnOS-Acceptance`。ZIP 内按本次 Build ID 分目录，双击该目录内的 AutumnOS.exe。此路径仅在构建时明确启用独立验收的字节中有效；同一用户的正式安装和存档均不需移动或复制。不要从 ZIP 内直接运行，不要覆盖已有验收目录。

独立验收构建只在游客测试数据中记录成功读档回执所对应的值摘要（不记录内容或文件路径），用于与该次测试的存档字节做对照。正常关闭时先向原 STA 请求关闭，断管或未收到回执另记为未确认；两种情况都以原始进程组的内核退出事实和清理结果决定能否释放租约。
