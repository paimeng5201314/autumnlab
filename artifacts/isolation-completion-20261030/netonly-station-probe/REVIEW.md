# NETONLY automatic window station metadata draft

Producer: 派蒙. Source implementation only; build, protocol self-test and real native trial are **not_run** for this snapshot. Existing clipboard evidence and code are unchanged.

The fixed apphost is `AutumnOS.NetOnlyStationProbe.exe`. No arguments exits 0 without entering any native probe. `--self-test <absolute fresh report>` invokes only the actual protocol/parser, manifest string gates, result gates and token comparison gates, with in-memory streams and constructed facts (19 cases, currently not_run). `--execute <absolute frozen manifest>` creates `case_root/netonly-case-<nonce>/report.json`. Root owns the preparation/build/run wrappers and a fresh execution authorization is required before the latter entry is run.

The schema-1 manifest binds `source_snapshot_id` (`sha256:` and 64 lowercase hex), an existing local D-volume `case_root`, `payload_directory`, fixed `executable`, and the complete `files` array (`path`, `bytes`, `sha256`). The current apphost must be that exact entry. Manifest and all publish files remain pinned with read-only `FileShare.Read` handles for the complete run. Reparse ancestors, relative escapes, duplicate paths and incomplete sets are rejected. System/profile files and existing ACLs are not modified.

The ordinary medium parent makes at most one `CreateProcessWithLogonW` call, using only `LOGON_NETCREDENTIALS_ONLY` (2), random synthetic local username, domain `.`, and a synthetic random password. No real credentials are read; the password stays out of the command, environment, protocol and reports. Temporary password char/unmanaged buffers are cleared; no immutable password string is created. The explicit desktop is `WinSta0\\Default`. A minimal caller-independent Unicode environment excludes profiler/startup hooks. The same complete frozen WinExe is launched suspended; no standard handle inheritance is requested.

Before resuming the original returned thread, the parent queries the original process token: user SID hash, token session, integrity, elevation and AppContainer must equal the parent, AuthenticationId must differ, and both present and enabled privilege LUID sets must be subsets of the parent's respective sets. The image path must equal the pinned apphost. Original handles remain held until observed signaled, not reopened by PID. Pre-resume failure still attempts to resume this known metadata-only child for natural exit. A wait failure or live child remains pending; a timer is never treated as exit and there is no termination API.

The local named pipe is `CurrentUserOnly`, with 4-byte length-prefixed strict UTF-8 JSON (4096-byte maximum). Nonce and kernel pipe peer PID must bind the original child. The child independently verifies its live original parent handle, pinned image path and token relation before authenticating the server PID. Only `hello -> ready -> create -> result -> ack` is accepted. No arbitrary path/SDDL/command is transported. Parent exit and a finite protocol observation budget reject missing messages; pipe closure causes the child to stop without retrying station creation.

The child calls `CreateWindowStationW(NULL, CWF_CREATE_ONLY, ...)` once, only after admission. The automatic name is read from the actual returned handle rather than predicted from an undocumented naming convention. An existing-name failure is reported and never reopened or retried. The new security descriptor has only current user and SYSTEM full-access ACEs, a protected DACL, owner/group equal current user, and a Low no-write-up label. Actual owner/group/two ACEs/protection/label/nonvisible/noninheritable flags and exact name are read back. If the API changed the process station association, the child restores its borrowed original station before closing its sole owned station handle. The protocol's `original_handle_closed` means the original handle returned for the **created** station; the borrowed original WinSta0 handle is never closed. No desktop, window, clipboard, browser, network, input switch, profile, policy or service operation is implemented.

After the original child handle is signaled, the parent independently opens the exact returned station name with only `WINSTA_READATTRIBUTES` (2), no inheritance. Only NULL with native error 2 or 3 proves absence. A returned handle is closed and is a failure; error 0/5/other is unproven. Cleanup and test outcome remain separate. Missing result/name after a crash never fabricates station absence. Report writing errors prevent exit 0 while original-child cleanup observation continues.

`completed_netonly_station_metadata_only` proves only the bounded metadata experiment, not AutumnOS isolation, credential authentication, production compatibility, or LSA session destruction. NETONLY creates a real new LSA logon context and may notify network providers even though the application invokes no network API. `lsa_cleanup` is always `not_claimed`; process/station closure does not claim system logon-state cleanup. Future real execution requires specific authorization covering these effects. This package has not been executed.

Primary API references:

- [CreateProcessWithLogonW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-createprocesswithlogonw): NETONLY does not validate supplied credentials, creates an LSA session, and process creation does not prove DLL initialization.
- [CreateWindowStationW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-createwindowstationw): NULL uses the calling logon session identifier; CWF_CREATE_ONLY rejects an existing station.
- [SetProcessWindowStation](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setprocesswindowstation), [CloseWindowStation](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-closewindowstation): association and original handle lifecycle require explicit checking.
- [GetNamedPipeClientProcessId](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getnamedpipeclientprocessid) and [GetNamedPipeServerProcessId](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getnamedpipeserverprocessid): kernel peer PID checks complement nonce and original process handles.
