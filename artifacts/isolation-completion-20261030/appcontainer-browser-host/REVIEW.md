# 待执行机制的范围与影响

制作人：派蒙。此文供根负责人和派蒙审阅；它不是执行授权，也不是通过报告。

2026-10-30实测后修订：原控制台子程序在普通A中附带创建了精确System32/conhost.exe，树外进程门禁因此正确拒绝网页加载。两次原始失败均保留，没有创建B的profile。宿主改用WinExe子系统，继续仅通过STARTF_USESTDHANDLES继承的两个匿名管道通信，以避免创建额外控制台宿主；此修订的实际运行和清理结果由后续独立case报告证明，不添加conhost放行规则。

本目录允许的编译只读取工程内固定工具链和依赖，写入本目录的锁、obj/bin/publish及构建报告。编译不启动此EXE、不新建AppContainer profile、不更改ACL或全局策略。脚本由集成负责人统一管理。

真实试验需父审计器分别启动普通A与AppContainerB，同一子程序字节、同一固定浏览器版本、同样全新专属UDF，且须已有对应范围授权。父程序负责精确新profile、新对象ACL、原始句柄、token/SID/能力、运行进程映像身份及全组退出的独立证据。本子程序不实施这些权限变更，不访问任何既有用户数据。子程序路径不是生产运行入口。

浏览器启动可能创建renderer、utility和其它辅助进程以及新的浏览器缓存。SDK清单会遗漏部分辅助进程，因此必须另用OS原始进程关系与句柄证据核对，不能根据页面自述认定全部进程受限。普通A/B必须有完整正控和真实执行证据。AppContainer=1、caps=0或句柄访问拒绝不能单独证明浏览器剪贴板边界。

实际显示一个不主动抢焦点的自有诊断窗口，页面有canvas动画和内存WASM；没有桌面输入自动化、剪贴板操作、联网探针、真实账号、第三方内容、安装/更新、外部协议。固定生产CSP/Connection-Allowlist/Permissions-Policy从首次自有资源响应生效，Chromium沙箱不关闭。此页不是产品挑战，不能作为第三方运行证明。

初始化失败和超时保留精确阶段、HRESULT与原生数字错误码，不输出任意异常文本、账号资料或环境值。关闭只请求普通控件/浏览器关闭；有限观察结束仍缺退出证据时退出1并明确 `unproven`。父程序必须保留所有相关新目录/profile和原始进程句柄，继续观察，不强杀或先删除再声称清理。不能用反复加权限、关闭系统保护、重命名规避拦截等方式把试验改成通过。

本程序尚未编译/执行时状态为 `not_run`。真实编译结果、固定依赖锁、源文件SHA256及发布逐文件SHA256必须由实际构建清单另证；运行成绩必须独立报告，不能在此预填。G1完整通过前不接入生产，不修改统一拒绝路径。
