# 04 · GitHub 商店与更新合同

## A. 发现与分类

发现查询基线：`topic:autumnos-app is:public`。GitHub 支持 Topic 搜索；仓库管理员可自行添加 Topic，因此分类不等于认证。[S5][S6]

分类状态：pm（自标、未核验）、sq（社区自标）、未分类、pm/sq 冲突。页面显示仓库所有者和 repositoryId。没有任何由派蒙维护的认可名单，也不为它预先创建一个空后台。

发现不等于可安装。只有存在兼容的 Release 与正确的 .autumn 附件，才提供安装按钮。只有源代码压缩包、草稿版本、破损清单、不兼容 SDK、架构不匹配或附件缺失时显示明确原因。

GitHub 搜索按需分页、缓存、去重、延迟加载详情、退避重试；处理结果不完整标志与索引延迟，不承诺实时穷尽全 GitHub。分页和筛选的作用域要显示清楚，不能把当前页结果称为全站统计。

## B. 三种清单

- 仓库根 `autumn.store.json`：应用显示名、介绍、分类、截图与开发者信息；每次获取记录 commit/ETag/时间。
- Release 附件 `autumn.release.json`：schemaVersion、appId、应用版本、渠道、运行时、最低宿主/SDK、安装附件、字节大小、SHA-256、权限摘要与存档格式要求。
- 包内 `manifest.json`：同一身份与版本、实际入口、资源、声明权限、生命周期、快捷操作等运行合同。

Release 清单与内部清单必须核对，appId、版本、入口和权限不一致拒绝安装。schema 中区分必填、可选、未知字段和版本升级规则；正式示例由工具生成，不能手写一套与解析器不一致的 JSON。

初期一仓库一应用。附件为开发者的安装产物，不使用 GitHub 自动提供的源码 ZIP 代替。[S8]

## C. 安装与应用版本

选择版本后：检查兼容/空间/权限变化 → 下载暂存 → 验证传输完整性与可用的来源签名 → 安全解包 → 校验清单 → 安装提交 → 注册 → 通知桌面。

安装器禁止绝对路径、.. 越界、符号链接/重解析点绕过、大小写冲突、重复危险条目、压缩炸弹和任意安装脚本。解包总量和文件数量有上限。解包文件不在验证完成前执行。

未签名或自签的社区包不能被称为“官方可信”。哈希验证只解决与所取得清单的一致性；不证明开发者身份或代码安全。首次来源确认后固定 repositoryId，并记录签名连续性（存在时）；来源变化不静默接受。

运行中的应用不直接替换资源。升级前保存与关闭实例，隔离 staging 与用户数据；失败回到上一安装记录。旧版降级先检查存档格式，可备份后明确选择。固定版本阻止自动更新。

详情筛选：来源、分类、稳定/预览、兼容性、运行环境、离线能力、已安装/有更新；版本列出发布时间、说明、空间、权限差异。应用的预览设置独立于主程序设置。

## D. 下载与代理

设置分为系统代理与 GitHub URL 加速。URL 加速只改写允许的 GitHub API/Release 请求；默认不代理认证信息。OAuth、Logto、刷新令牌、第三方应用流量不受该设置控制。

模板必须验证协议、占位符、目标主机和嵌套 URL 编码，拒绝凭据出现在 URL。API 加速与附件加速可分开，默认元数据直连；发生新主机重定向时不携带 Authorization。TLS 验证不可关闭。

支持连接测试、超时、退避、取消、进度、并发、限速、历史、恢复与直连回退。只在资源身份与 Range 响应一致时恢复；HTML 错误页、长度不符、hash 错误均失败。缓存记录来源与时间，不保存令牌。

没有 GitHub PAT 时也能使用公开浏览和下载路径；不得给所有客户端内置共享个人 PAT。用户自行授权的凭据须安全存放且不转交未知代理。

## E. 主程序渠道与候选

更新来源：`paimeng5201314/autumnlab`。

| 开关 | 可选 Release Tag 示例 | 清单 channel | 清单 version |
|---|---|---|---|
| 关闭预览 | plus-v0.1.0 | plus | 0.1.0 |
| 开启预览 | meta-v0.2.0-preview.1 | meta | 0.2.0-preview.1 |

示例只是格式，不是已发布版本。每个版本独立不可变；不反复移动 plus/meta 固定标签。Tag、清单 channel、版本与 prerelease 状态需匹配。不自动订阅另一渠道，不按发布时间或字符串判断较新，不自动降级。

遍历发布列表做规范版本比较；不能用仅正式版语义的 latest 接口代替预览选择。[S8]

`autumn.update.json` 记录 schemaVersion、channel、version、targetRid、最低更新器、payload 及 hash、签名 keyId、数据迁移与回退要求。对完整清单原始字节使用定义明确的签名格式；客户端固定验证公钥。私钥不在客户端。密钥轮换要有受旧可信根验证的路径，不能接纳下载源附送的任意新公钥。

## F. 安全提交状态机

Idle → Checking → Available → Downloading → Verifying → Staged → WaitingForIdle → AcquiringMaintenance → Rechecking → SavingState → Handoff → Applying → HealthCheck → Committed。

失败分支进入明确 Error/Recovery/RolledBack；恢复日志须足够识别上次中断位置，不无限循环自动重试破损候选。

游戏在 Starting、Foreground、Background、Suspended、Closing 状态均阻塞提交。关键保存、下载后的安装提交、备份恢复和数据迁移也阻塞。后台检查/下载允许，但游戏有带宽需求时遵守限速设置。

维护锁统一阻止新实例启动并等待现有关键操作完成；进程切换时必须有可验证的锁/状态交接，避免主程序退出瞬间新启动器闯入。多个客户端实例和用户重复点击启动也要测试。

独立更新器运行在不会被本次替换破坏的有效目录；再次验证清单、payload、目标根和安全路径。只替换发布清单指定的程序文件，永不整体覆盖 AutumnOS_Data。暂存和目标同卷；关键切换采用经验证的恢复策略，不承诺整个多文件覆盖天然原子。

新程序启动后完成核心初始化并发送健康确认。失败则恢复旧代码；数据迁移必须有可恢复策略或明确阻塞回退，不能让旧代码读取已不可逆变更的数据。保留故障报告并允许用户手动恢复，不形成无限崩溃循环。

## G. 双包发布

便携包与安装包使用同一构建版本。默认安装到用户可写路径，使数据根规则与自更新保持一致；不是假设 Program Files 可直接写入。记录安装/卸载对数据的行为，默认不删存档。

WebView2 可选固定运行时随包方案或被验证的依赖部署方案；便携离线首次运行必须真实测试。固定版运行时不会自行更新，维护责任写入更新计划。[S3]

首个公开版本发布前，用本地测试 feed 或单独测试环境进行旧版→新版→失败恢复演练。尚无公开历史版本不是跳过更新测试的理由；不能为了测试把假 Release 发布到正式仓库。
