# 05 · 发布质量门禁

制作人：派蒙。今天是目标，不为未经验证的结果提供豁免。

## 发布候选定义

任何发布候选关联唯一源文件快照ID/内容哈希（本地commit可附加）、依赖锁、构建环境、Windows 实测、产物 hash、发布渠道与范围。自动检查通过并不等于 UI 体验通过。完整确认范围尚未完成时，不能声明完整发布。

meta 可以表达预览成熟度，但不能豁免安全、存档、真实安装与更新恢复。任何缩小范围的公开预览先取得派蒙明确同意，不能把缺陷随意改名成预览特性。

## Windows 测试矩阵

Windows 10 22H2 与至少一个实际目标 Windows 11 构建分别记录。测试 x64、标准用户、便携与安装、无预装 .NET、离线首启条件、缺失 WebView2 的处理、不同 DPI、中文输入法、中文/空格路径、窗口缩放、最小化/恢复。

WebView2 与 WinUI 的层叠、遮罩、长按菜单和多任务切换须实测：不能在游戏画面上弹出不可点击或被遮挡的系统控件。外部游戏窗口、浏览器标签或网页静态预览不算内部运行验收。

## 零容忍项

账号跨应用/跨用户泄漏、任意宿主执行、关闭沙箱或证书验证、存档被覆盖、未经签名验证的无人值守更新、错报安装成功、虚构测试通过、不可用 EXE 冒充产物。

不是所有小问题都必须完全消失，但任何已知问题必须记录严重度、影响和重现步骤；不允许在没有证据时写“全部正常”。

## 性能与视觉

在文档中先指定参考硬件、窗口尺寸、DPI、测量方法和目标值，再记录启动、动画、输入延迟、前后台 CPU/GPU/内存、安装下载响应。不能仅写“60fps 流畅”而不测量。减少动态效果模式、低性能回退和快速取消操作也要验收。

## 产物清单（待真实构建）

AutumnOS-<version>-win-x64-portable.zip；AutumnOS-<version>-win-x64-setup.exe；版本对应的更新 payload；autumn.update.json 及签名；校验清单；SDK/模板；对应版本的开发文档；变更记录；测试与兼容性报告；第三方声明。

这些是目标文件名，不是当前开发包里已经有的客户端产物。Windows Authenticode 发布者信息必须真实；没有证书就如实说明，不能伪造“派蒙已认证”的系统弹窗，也不能要求关闭系统保护。

## 发布流程

冻结本地候选源文件快照/内容哈希 → 全部门禁 → 生成并验证产物 → 派蒙审阅范围/署名/已知问题 → 明确批准发布动作 → 创建匹配渠道的不可变版本 → 从真实下载入口再次安装验证 → 记录发布证据。

修改候选代码后，受影响的构建与测试证据必须重跑；不把旧源码快照的截图和新二进制混用。发布失败保留候选和日志，不重新上传同版本不同内容来掩盖错误。

## 当前执行截止点

当前仅批准本地开发和候选交付。上面的公共发布流程是未来操作规范，不是本次上传授权；本轮完成本地构建、全量验收和候选打包后停在派蒙审阅环节。没有GitHub账号、Git历史或Actions运行不是本地交付阻塞；安全、数据、权限及恢复检查不能因此省略。

## T02 启动器单实例增量门禁

R058/A058 以同用户/登录会话的业务主实例、原窗口和游戏会话验收；允许短暂转发进程与 WebView2 子进程。用两个真实编译的不同版本和多个发行目录验证数据不串用，保留最小化/最大化、冷并发、无响应/断管、退出及隔离崩溃证据。测试只持有并清理自己创建的进程；发现既有用户窗口时停止测试，请用户正常退出。
