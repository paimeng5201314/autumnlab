# AutumnOS 工程执行规则

产品名称：Lab Chronicles AutumnOS。制作人：派蒙。用户入口：AutumnOS.exe。

## 不可自行改变的产品边界

- Windows 10 22H2 / Windows 11，win-x64；默认普通窗口，可最大化；便携版与安装版均在交付范围。
- 启动时确保启动入口所在目录中的 AutumnOS_Data 存在；已有内容必须保留。不是每次新建不同目录，不是进程工作目录。
- iPad 风格桌面、hello 首启、AutumnOS 品牌过渡、设置、长按菜单、桌面编辑、Dock、文件夹、搜索、多任务和个性化；使用原创或获许可素材，不替换成普通列表启动器。
- 第三方只能安装 .autumn，并在 AutumnOS 内部呈现；不提供任意 EXE 导入，不启动外部游戏窗口冒充内部运行。
- 采用 C# / .NET 原生外壳；工程验证基线为 .NET 10、WinUI 3、WebView2 与 Web/WASM 应用。先实测运行与隔离边界，失败则报告并记录架构决策，不能私自改为网站、Electron 或外部 EXE 方案。
- 商店直接发现 GitHub topic:autumnos-app 的公开仓库，从 Releases 获取安装包和版本。pm/sq 依用户标签分类；本轮不建设认可名单、审核后台或认证服务。
- pm 只能显示“PM／受认可（仓库自标，未核验）”等带解释的分类文案，不能显示“官方审核通过”“已安全认证”。所有类别使用同一权限和安全检查。
- 主程序只从 paimeng5201314/autumnlab 检查更新；正式渠道 plus，预览开关开启时 meta。必须在无游戏会话且无关键写入时提交更新。
- Logto 系统浏览器登录 + OIDC/PKCE；第三方应用按权限获得最小资料，不获得宿主登录令牌。
- 保留当前已确认的完整范围，不因为发布目标自动删减，也不把不工作的功能藏到“高级功能”后标为完成。

## 工程规则

先检查当前本地文件夹与环境；不要求.git或远端；保留现有 LICENSE 和用户修改。版本依赖通过当前官方文档核验并固定，不使用浮动最新版；SDK 版本、运行时版本和应用协议版本分别记录。

同一本地项目模块化，公共接口由集成负责人审核。系统 UI 通过服务接口操作，不能直接修改另一个模块的数据。公开 SDK 不暴露主程序内部管理接口。第三方代码不加载为宿主进程中的任意 DLL。

一次只完成一个清晰阶段或独立工作包，并形成真实可审查的本地改动。共享 schema、解决方案、依赖文件、应用注册表模型和发布工作流不能由多组无协调地同时修改。

## 安全和发布规则

禁止假登录、假安装、假下载进度、假云同步、假测试报告、禁用 TLS 验证、泄露令牌、关闭 WebView2 沙箱、越界解压和下载后不验证就执行。

测试替身仅放在测试或开发配置；发布构建不能自动退回假服务。缺失真实 Logto 配置时显示 AUTH_NOT_CONFIGURED 并记录发布阻塞，不返回假用户。未实现的能力返回明确 CAPABILITY_UNAVAILABLE，不能返回假成功。

主程序更新使用与仓库分类无关的发布签名信任根。签名私钥仅在受控签名环境；客户端只持公钥。没有发布签名时不能启用无人值守自动替换。签名、哈希和 Windows 发布者证书是不同验证层，不混淆。

制作人信息集中管理并覆盖启动页、关于、首次设置完成页、安装程序、README、发布说明。保留第三方版权和已有项目许可；不要用“制作人”代替证书中真实的发布者身份。

未经明确的发布操作授权，不创建公共发布或移动标签；先交付候选和证据。遇到阻塞，完成其他独立工作并准确报告，不以删除测试或关闭保护来通过。

## 每个阶段必须交付

真实实现、受影响接口的文档、最小可运行示例、自动测试、必要 Windows 实测、执行命令及结果、未通过项、下一阶段交接。

只在实际运行后使用“通过”。Linux 上源码分析或构建配置生成不能代替 Windows UI、便携版、安装版与升级实测。每次阶段报告记录源文件快照ID/内容哈希（commit仅在已有且获准使用时附加）、依赖版本、环境、任务 ID、测试 ID 和产物位置。

## 本地工作区规则（v0.3）

开发位置是用户当前打开的本地文件夹，不是远程GitHub仓库。普通空文件夹即可作为起点；没有.git、没有远端、没有GitHub授权都不阻塞开发。用户没有授权克隆、拉取、推送、创建远端仓库、PR、公共Release或云端任务，不执行这些操作，也不把它们列为开工前置条件。

先检查当前本地文件，保留已有源码、LICENSE、README、AGENTS.md和用户改动；没有文件就按阶段创建，不通过读取远端覆盖本地。Git仅可作为用户另行同意后的可选本地版本工具，不擅自初始化或提交。没有Git时用本地源文件快照清单/内容哈希及构建ID关联证据。

商店发现和更新检查继续按产品规范访问GitHub；这不授权上传项目或同步远端源码。读取官方开发文档、恢复依赖、Logto真实登录和商店只读集成可以按工具权限进行。本地工作区不是要求所有服务离线，也不是对模型运行位置作承诺。

构建、测试、运行和打包优先使用本机Windows工具链及本地脚本。必需的自动化检查在本地可执行；GitHub Actions、云端CI、远程发布只作为以后另行授权的部署选择，不阻塞当前交付。保留工具审批，不关闭沙箱或系统保护来绕过权限问题。

本机环境缺少组件时报告具体缺项和需要用户批准的安装，不改换技术路线、不虚报构建成功。源码、测试报告、开发文档和最终便携/安装候选都输出到本地。进度记在AUTUMNOS_PROGRESS.md。
